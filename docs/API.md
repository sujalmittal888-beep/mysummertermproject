# TaskFlow API Reference

Base URL (local): `http://localhost:8000`

Interactive documentation is auto-generated by FastAPI:

- Swagger UI: `GET /docs`
- ReDoc: `GET /redoc`
- OpenAPI schema: `GET /openapi.json`

All request and response bodies are JSON unless noted otherwise.

---

## Conventions

### Pipeline ID

Most resources are keyed by a `pipeline_id` — a 12-character hex identifier
generated when an instruction enters the system. All artifacts, validation
reports, and graph payloads for one run share the same `pipeline_id`.

### Error envelope

Errors are returned as:

```json
{
  "detail": {
    "error": "SchemaValidationError",
    "message": "Human-readable explanation",
    "issues": []
  }
}
```

| Domain error            | HTTP status |
|-------------------------|-------------|
| `SchemaValidationError` | 422         |
| `DomainRuleError`       | 422         |
| `LLMProviderError`      | 502         |
| `ArtifactNotFoundError` | 404         |
| Unhandled error         | 500         |

## Endpoints

### `GET /health`

Liveness probe. No side effects.

**Response `200`**

```json
{
  "status": "ok",
  "version": "1.0.0",
  "llm_provider": "mock"
}
```

---

### `POST /instructions`

Runs the **full pipeline**: LLM parse → schema validation → business rules →
graph build → 7-stage graph validation → artifact export.

**Request**

```json
{
  "instruction": "Pick the red box from Shelf A, inspect it, and place it on Conveyor Belt 3."
}
```

**Response `201`**

```json
{
  "pipeline_id": "32cb7816d540",
  "valid": true,
  "task_count": 6,
  "validation_report": { "...": "see /validation/{id}" },
  "artifacts": [
    "task_plan.json",
    "validation_report.json",
    "task_graph.png",
    "task_graph.html",
    "task_graph.graphml",
    "task_flow_package.zip"
  ],
  "download_base": "/downloads/32cb7816d540"
}
```

Notes:

- The pipeline **stops after export**. No execution occurs.
- If graph validation fails, the response is still `201` with `valid: false`
  and a populated `validation_report` — a structurally parseable but logically
  invalid plan is a *result*, not a transport error.
- Transport-level errors (unparseable LLM output, schema violations) raise the
  error envelope above instead.

---

### `POST /parse`

Stage 1 only: natural language → validated JSON task schema. No graph, no
artifacts.

**Request**

```json
{ "instruction": "Scan all containers on Shelf B and sort damaged ones." }
```

**Response `200`**

```json
{
  "pipeline_id": "a1b2c3d4e5f6",
  "plan": {
    "version": "1.0",
    "instruction": "Scan all containers on Shelf B and sort damaged ones.",
    "tasks": [
      {
        "id": "T1",
        "action": "navigate",
        "description": "Navigate to Shelf B",
        "depends_on": [],
        "condition": null,
        "metadata": { "location": "Shelf B" }
      }
    ]
  }
}
```

---

### `POST /graph`

Builds a NetworkX DiGraph from a previously parsed plan, or from a plan
supplied inline, and returns a serializable graph payload (node-link format).

**Request**

```json
{ "pipeline_id": "a1b2c3d4e5f6" }
```

or

```json
{ "plan": { "version": "1.0", "instruction": "...", "tasks": [] } }
```

**Response `200`**

```json
{
  "pipeline_id": "a1b2c3d4e5f6",
  "graph": {
    "directed": true,
    "nodes": [
      {
        "id": "T1",
        "task_id": "T1",
        "action": "navigate",
        "description": "Navigate to Shelf B",
        "condition": null,
        "metadata": { "location": "Shelf B" }
      }
    ],
    "edges": [
      {
        "source": "T1",
        "target": "T2",
        "dependency_type": "sequential",
        "conditional": false
      }
    ]
  }
}
```

---

### `POST /validate`

Runs the 7-stage graph validation engine against a stored or inline plan.

**Request**

```json
{ "pipeline_id": "a1b2c3d4e5f6" }
```

**Response `200`** — see [Validation report shape](#validation-report-shape).

---

### `POST /export`

Generates all six artifacts for a stored plan and returns download paths.

**Request**

```json
{ "pipeline_id": "a1b2c3d4e5f6" }
```

**Response `200`**

```json
{
  "pipeline_id": "a1b2c3d4e5f6",
  "artifacts": [
    "task_plan.json",
    "validation_report.json",
    "task_graph.png",
    "task_graph.html",
    "task_graph.graphml",
    "task_flow_package.zip"
  ],
  "download_base": "/downloads/a1b2c3d4e5f6"
}
```

---

### `GET /graph/{pipeline_id}`

Returns the stored graph payload for a pipeline run. `404` if unknown.

---

### `GET /validation/{pipeline_id}`

Returns the stored validation report for a pipeline run. `404` if unknown.

---

### `GET /downloads/{pipeline_id}/{artifact}`

Streams a single artifact file. The `artifact` segment must be one of the six
whitelisted filenames; anything else (including path traversal attempts) is
rejected with `404`.

| Artifact                 | Content type               |
|--------------------------|----------------------------|
| `task_plan.json`         | `application/json`         |
| `validation_report.json` | `application/json`         |
| `task_graph.png`         | `image/png`                |
| `task_graph.html`        | `text/html`                |
| `task_graph.graphml`     | `application/xml`          |
| `task_flow_package.zip`  | `application/zip`          |

## Validation report shape

```json
{
  "valid": true,
  "cycle_check": "passed",
  "dependency_check": "passed",
  "reachability_check": "passed",
  "action_check": "passed",
  "conditional_check": "passed",
  "structural_check": "passed",
  "consistency_check": "passed",
  "issues": [
    {
      "check": "conditional_check",
      "severity": "warning",
      "message": "Task T4 has a single conditional child; the opposite branch is unhandled.",
      "task_id": "T4"
    }
  ],
  "node_count": 6,
  "edge_count": 6,
  "timestamp": "2026-06-10T18:31:02.114325+00:00"
}
```

- `valid` is `true` only when **no error-severity issues** exist; warnings do
  not fail a plan.
- Each `*_check` field is `"passed"` or `"failed"`.

## End-to-end example (curl)

```bash
# 1. Run the full pipeline
curl -s -X POST localhost:8000/instructions \
  -H 'Content-Type: application/json' \
  -d '{"instruction": "Pick the red box from Shelf A, inspect it, and place it on Conveyor Belt 3."}'

# 2. Fetch the validation report
curl -s localhost:8000/validation/<pipeline_id>

# 3. Download the bundle
curl -sOJ localhost:8000/downloads/<pipeline_id>/task_flow_package.zip
```
